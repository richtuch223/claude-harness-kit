# Changes, 2026-10-14

This build ports what the source program added after the 2026-10-09 build, adds the Codex-on-top-of-Claude
guide the kit had been missing, and fixes one defect found in the kit's own files. Program-specific names,
venues and figures were stripped; mechanisms and the reasoning behind each check were kept.

## New headline doc: `05_CODEX_ON_TOP.md`

How to put a GPT-family seat beside Claude Code on a ChatGPT subscription through OAuth (no API key, a
separate quota): install and login, the two seats (review gate via `tools/verify.py -p codex-cli`, web scout
via `tools/codex_scout.py`) and what each may see, the hardening a read-only sandbox does not give you (the
three tool switches, `--strict-config`, `--ephemeral`, the canary after every upgrade), pinning model and
effort instead of inheriting `~/.codex/config.toml`, probing model ids, panels, running the two side by
side, and a pre-flight checklist. The Gemini CLI OAuth route is covered as the unhardened fallback.

## New tools (`kit/tools/`)

- **`codex_scout.py`** (the source program's web-recon scout, genericized): fans out web-research prompts on
  the Codex seat with web search ON and shell/exec OFF, from an empty scratch cwd, `--strict-config` and
  `--ephemeral`. Model from `--model` or `CODEX_SCOUT_MODEL` (never the CLI default); effort pinned and
  printed in each report header with the UTC time and return code; a failed or timed-out run overwrites any older
  report at the same path. `--canary` is a live isolation probe (a temp file with a random token; PASS only when
  rc=0, the final message says `CANNOT_READ`, and the token appears nowhere); it passed on codex-cli 0.155.1
  during this build. PASS is the outcome of that probe, not a proof about every tool Codex could expose.
- **`fetch_guard.py`**: `check_json(raw, expect, require_keys, nonempty)` validates an API reply before it is
  parsed, cached, or written to a ledger: empty/non-JSON bodies, top-level error keys, wrong type, missing
  nested keys, empty collections, invalid UTF-8, and the non-JSON constants `NaN`/`Infinity`. `FetchInvalid` is a
  retryable failure, never a value. A float that overflows to infinity (`1e400`) is rejected too. Selftest 18/18.
- **`memory_lint.py`**: read-only linter for the per-project memory directory (frontmatter parses, `name`
  matches the filename, valid `type`, `status`/`superseded_by` consistency, `MEMORY.md` pointers resolve,
  unindexed files, dangling `[[links]]`). No personal default path: `--dir` or `MEMORY_DIR`. Selftest passes.

## `tools/prestate.py`: no-op amend guard

`amend` now refuses an amendment whose normalized text equals the current head (exit 2 with the likely
cause: the edit before it did not apply). `--allow-noop` records it anyway. The selftest gained the case on
its own log. The source program had logged two such no-ops after silent text-replace failures.

## `tools/verify.py`

`--reasoning xhigh` accepted (the source program's event gates run there).

## `optional/checkpoint-writer/`

A `PreCompact` hook that writes `ops/checkpoints/<UTC>.md` before context compaction: last commit,
working-tree counts, recently touched folders, frozen `SPEC*.md`, retracted registry ids, and headed blanks
for objective / phase / next action. Fail-open, one overall time budget below the hook timeout (a section that
runs out says so; the file is always written), heavy folders pruned from the spec scan, same-stamp collision
guard, `SessionStart` fallback with an explicit header note. Ships with a README and a settings snippet;
selftest passes on a throwaway repo.

## `fleet` skill

Two additions to the contract: CLI seats always get an explicit effort (the config-file default is applied
silently), and the trap list names "an API error body parsed or cached as data" with the guard call.

## Lessons (`lessons/`)

Three new: an API error body cached as data (three hits in one week; the guard above); an amend run after a
failed edit records a no-op; the desktop hard-rebooted under an all-core numeric job beside six agent/CLI
processes, display-driver starvation being the unproven hypothesis (cap threads, two heavy jobs at once).
