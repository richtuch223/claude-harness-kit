# Changes, 2026-10-09

This build ports the generic parts of what the source program added since the 2026-09-25 build: three
new fan-out/research skills, six new measurement/discipline tools, a pre-commit gate for a bug the
source program hit twice, five new lessons, and a methods-canon template. Program-specific findings,
venues, tickers, dollar figures and names were stripped; mechanisms and the reasoning behind each check
were kept.

## Two real bugs fixed in THIS kit

While porting the frontmatter pre-commit check (below), running it against the kit's own shipped files
found that `kit/.claude/agents/adversarial-verifier.md` and `kit/.claude/agents/investigator.md` both had
an unquoted `: ` inside their `description:` field — exactly the defect the new check exists to catch.
Both descriptions are now properly quoted and verified to parse with `yaml.safe_load`. Every other
shipped agent/skill file was checked too; no others had the defect.

## New skills (`kit/.claude/skills/`)

- **`fleet`** — the contract for any multi-agent fan-out: a seat-routing table (scout / cheap / strong /
  cross-family reviewer / design-gate), effort tiers, a FLEET CONTRACT block to paste verbatim at the
  top of every agent prompt, rules for the agent that writes a pre-stated rule for a probe, a
  declared-read/write concurrency rule for running agents in parallel safely, a report schema, and a
  cost-per-accepted-finding ledger recipe (`tools/fleet_ledger.py`).
- **`conjecture-brief`** — the generator half of a research loop: a shared brief template (ships as
  `TEMPLATE.md`) that chains one fleet's result into the next fleet's starting point, with a fixed fill
  order (closed-ledger search first, then established facts, then the conjecture itself, payer box,
  kill conditions with a joint-pass-probability check, mandatory null controls, fixed lanes, hand-off).
- **`frontier-audit`** — a periodic, re-read-only meta-audit: re-type closures, census failures by
  law, rank near-misses by cost-to-clear, run a sampling-bias census, and produce a ranked list of where
  the next scout budget should go. Never changes a verdict itself; proposed reclassifications go to a
  design/closure gate as one batch.

## `screen-proposal` additions

- **§0a** — name the closest failure law (`docs/METHODS.md` §1) before designing anything; no named
  difference from a known law is an automatic REJECT.
- **§0a2** — obscurity is not protection: a searched-for signal shrinks out of sample whether or not it
  is published, so "nobody has found this yet" is never itself evidence of persistence. Only forward or
  own-fill evidence establishes a real edge. (This does not say obscurity is worthless when the barrier
  is access/capacity/operations rather than knowledge — only that it earns no automatic credit.)
- **§0b** — a literature gate: read the 2-3 strongest papers in full before any probe touches data, write
  a one-page mechanism memo, score anchor papers on the rigor rubric, set the kill threshold relative to
  the published effect size, and regress any PASS on the nearest free factor/portfolio before trusting it.

## New tools (`kit/tools/`)

All six ship a working `--selftest` (verified to pass in this kit's own `tools/` directory) and take
their paths/config from arguments or the repo root, never a hard-coded absolute path.

- **`prestate.py`** — pre-statement/freeze helper: content-addressed, append-only log of what rule was
  frozen when, with an explicit AMEND record (never a silent rewrite) and a `conform` command that sends
  the full ROOT→CURRENT history plus the implementation to a cross-family reviewer
  (`tools/verify.py review`, provider/model configurable via `--provider`/`--model`, default a
  different-family tier alias) to check the code against the CURRENT rule, not a stale one.
- **`instrument_check.py`** — a mechanical "can this field actually observe the quantity it's named
  for?" gate: null share, dominant-mode detection, at-reference-value detection, zero-volume/carried-
  forward detection, API page-cap detection, order-violation detection, cross-reference mismatch
  (with a self-compare guard), a price-vs-reference PAIR_RATIO check, and a consecutive-row
  SPLICE_CHECK for vendor data-feed splices. Every flag is a mechanical count/share over every row
  supplied (never a sample), with fixed, fail-closed thresholds. Verdict is never PASS/KILL — an
  instrument null means NEEDS_DATA for the hypothesis under test, not a judgment on it.
- **`overfit_stats.py`** — Deflated Sharpe Ratio (Bailey & López de Prado 2014) and Probability of
  Backtest Overfitting via Combinatorially Symmetric Cross-Validation (Bailey, Borwein, López de Prado &
  Zhu 2017), pure numpy/pandas (no scipy). Advisory only; interpretation stays with a human/review gate.
- **`decay_monitor.py`** — a sequential monitor for a live/forward line's per-unit excess returns: a
  one-sided CUSUM (Page 1954) for early-warning decay detection plus a Wald SPRT (1945) for a terminal
  accept-H0/accept-H1 decision, run side by side with the overall state prioritizing a decided SPRT over
  a CUSUM alarm over CONTINUE.
- **`residual_mine.py`** — a GREEN (outcome-column-firewalled) residual miner: regress a cheap baseline
  out of a metric, then check whether what's left is a stable entity trait (persistent across a
  split-half AND a block-time split, with a long-panel variance-ratio check to separate a real trait
  from a random walk) versus noise or drift. Outputs ranked abduction SEEDS for `screen-proposal`, never
  a finding by itself. The outcome-column firewall is a REQUIRED `--forbid-cols` argument (or an
  explicit `NONE` declaration) plus a name-pattern refusal on anything that looks like an outcome
  column, checked recursively through derived-column expressions.
- **`fleet_ledger.py`** — one TSV row per agent fan-out (cost, agents, accepted findings, a `vein` tag)
  and an `mvt` command that flags a vein whose last two tagged runs both sit below the program's average
  yield — a flag, never an automatic stop. Ships with an empty `ops/fleet_ledger.tsv` (header row only).

`brain_export.py` was NOT ported: its source list (which files it bundles, with named section markers)
is tightly coupled to the source program's specific doc layout and a personal absolute default path for
an external memory file. Genericizing it would mean redesigning it around a config file of
(name, path, extract-markers) tuples — a larger rewrite than a straight port, so it was left out rather
than shipped half-adapted.

## Pre-commit hook (`kit/ops/githooks/`)

- New check: a staged `.claude/agents/*.md` or `.claude/skills/*/SKILL.md` whose frontmatter is missing,
  fails to parse as YAML, or lacks `name`/`description` now BLOCKS the commit. An unquoted `: ` inside an
  otherwise-ordinary English sentence is valid-looking text but invalid YAML, and Claude Code drops such
  a file silently — no error, no warning, the agent/skill just does not exist. The closing `---` must be
  its OWN line (not a substring match), so a value that happens to contain `---` cannot be read as the
  real closing fence.
- An optional `status: current|superseded` / `superseded_by: <name>` convention is validated when
  present: a `superseded_by` must point at an agent or skill that actually exists in the staged tree.
- `probe_pre_commit.py` gained 13 new cases exercising this check (missing, unparseable, incomplete,
  the fake-closing-delimiter case, and the status/superseded_by combinations); the suite is now 35/35.

## Lessons (`lessons/`)

Five new generic lessons: a secret-scanner test fixture must build the fake secret at runtime, not as a
literal; an unquoted `: ` in frontmatter silently drops the file (ported from the bug found and fixed in
this very build); never resolve a historical population through a current-only identifier list
(survivorship); free data APIs usually wall deep history even when live data is free; and a statistic
measured against its own in-sample mean carries that mean's shrinkage and cannot isolate a later,
specific event — pre-state the actual contrast.

## `docs/METHODS.md` (new)

A template methods canon: a failure-law table (two worked generic examples plus empty rows to fill in as
your own project accumulates twice-recurring failure patterns), a joint-pass-probability note for kill
trees, a validation-methods table pointing at the six tools above, the five-point rigor rubric (R1-R5,
also referenced from `screen-proposal` §0b), and an estimator-trap checklist.
