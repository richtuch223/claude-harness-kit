# Changes, 2026-09-25

This build carries fixes that landed in the source repo after the 2026-09-23 kit shipped. Each came out of
the cross-family review of the kit itself, was applied in the source repo first, and is ported here.

## Pre-commit hook (`kit/ops/githooks/`)

- The checker now scans `-diff` and binary-attributed files: the staged diff is read with `git diff --text`.
- The key-assignment pattern catches quoted keys (`"api_key": "..."` in JSON) and `application_key`.
- Python files are compiled from the staged bytes, not a lossy decode, so a file with invalid UTF-8 is blocked.
- `facts/registry.yaml` is parsed as strict UTF-8; bad bytes block the commit.
- The registry shape rule is keyed on `facts`: a `facts:` key that is not a list is blocked as WRONG SHAPE, and
  duplicate ids are found even when another list sits above `facts:`. A bare list, or a mapping with exactly
  one list, is still accepted.
- The Windows timeout kill (`taskkill`) is now bounded and cannot hang the hook.
- The "ok" line says when `SKIP_SELFTEST=1` skipped the selftests.
- New `probe_pre_commit.py`: 22 probes, each building a throwaway repo and checking that the hook blocks (or
  allows) for the right reason. One probe stages the kit's own `facts/registry.yaml` and expects it to pass.
  Run it after any edit to the hook.

## Figure hooks (`optional/figure-hooks/`)

- `verify_entry` refuses a blank quote, a blank value, and a value whose numbers share none with its quote.
  Numbers are compared whole, with sign and scale: `-2.8` is not `2.8`, `0.4k` is not `0.4`. Commas count
  only in groups of three, bare years are ignored, and a value whose only number is glued to a sign
  (`USD-2.8`) fails. The quote must appear verbatim, padding included. The old rule (every value number must
  appear somewhere in the source file) is replaced.
- The tripwire checks every occurrence of a retracted value against its own 150-character window, measured
  across line breaks. Markers are found in the full text at a word start, so a window edge can no longer cut
  "uncorrected" into "corrected", and "avoid" no longer counts as VOID. Phrase markers must also end at a word
  end. "CORRECT" is narrowed to CORRECTION, CORRECTED and INCORRECT.
- A retracted value that ends in a letter or digit no longer matches the head of a longer number (`$12` in
  `$12.5`, `$12,000`, or before a Unicode digit).
- The tripwire still warns when its state directory cannot be read or written; before, it went silent. State
  files are read and written as UTF-8.
- Both hooks treat a crash inside verification as "unverified", and the JIT hook shows only verified values.
- New `test_figures.py`: the source repo's 20 regression cases, three kit phrase-marker cases, tokenizer and
  verify probes, and end-to-end checks of both hooks (54 checks).

## Cross-family review tool (`kit/tools/verify.py`) and its docs

- The Codex route now runs `codex exec --strict-config -c features.shell_tool=false
  -c features.unified_exec=false -c tools.web_search=false -s read-only --ephemeral`. A canary probe on
  codex-cli 0.155.1 showed that `-s read-only` alone blocks writes and network but lets the reviewer read
  files outside its scratch directory. With the tools off, the same probe answered CANNOT_READ.
  `--strict-config` makes a key renamed in a future Codex fail the call instead of quietly restoring the shell.
  The selftest checks the flags.
- The Gemini CLI route is documented as NOT hardened against file reads.
- `02_VERIFICATION_LOOP.md`, the `cross-review` skill, and `README.md` no longer imply that the read-only
  sandbox stops reads.

## Share build

- The `reference/research-main/` copy of the source repo's own harness is removed: it carried domain research
  content. Pointers to it now describe the pieces instead.
- Lessons are made venue-neutral; memory metadata (session ids, private cross-links) is stripped.
